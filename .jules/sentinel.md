## 2025-02-18 - [Security Improvements]
**Vulnerability:** The application was vulnerable to Denial of Service (DoS) attacks and possible data leakage.
**Learning:** The `executeCommand` function lacked a timeout mechanism, potentially causing the app to hang or crash due to memory exhaustion if a command (e.g., `ping`, `top`, or reading endless logs) ran indefinitely. It also did not limit output, which could lead to OOM errors. When preventing thread hangs, we must ensure processes are reliably destroyed and that we don't inadvertently introduce deadlocks (like breaking an input stream read before destroying the process while waiting on it). Finally, Android backup was enabled, which could allow unauthorized extraction of sensitive data like command history from the Room database.
**Prevention:** Implement an external timeout coroutine that calls `destroy()` directly on the process to avoid blocking IO deadlocks, limit output stream ingestion size and safely break, ensure cleanup (`finally` block to destroy lingering process), and restrict `android:allowBackup` in `AndroidManifest.xml` when storing sensitive device data.
